# Node.js 后台管理系统 - 项目规划文档

> 从前端到全栈的学习项目  
> 创建日期：2026-08-11

## 📌 项目目标

通过开发一个完整的后台管理系统，掌握 Node.js 全栈开发技能，包含：
- 登录鉴权
- 权限控制（RBAC）
- 工单提交与审批
- 文件上传下载
- 日志记录
- RESTful API 设计
- 中间件机制
- 参数校验
- 统一返回结构
- 统一异常处理

---

## 🛠️ 技术栈选型

### 核心框架
- **Express.js** - Node.js Web 框架
  - 轻量级、易学习
  - 中间件生态丰富
  - 社区成熟，文档完善

### 数据库层
- **MySQL/PostgreSQL** - 关系型数据库
  - 适合权限管理的复杂关系
  - 事务支持完善
- **Sequelize** 或 **Prisma** - ORM 工具
  - Sequelize：成熟稳定，文档丰富
  - Prisma：现代化，类型安全（推荐）

### 认证授权
- **JWT** (jsonwebtoken) - 无状态认证
  - 适合前后端分离
  - 易于扩展（微服务）
- **bcrypt** - 密码加密
  - 行业标准
  - 防彩虹表攻击

### 文件处理
- **multer** - 文件上传中间件
  - Express 官方推荐
  - 支持多种存储方式

### 参数校验
- **joi** - Schema 校验
  - 声明式校验
  - 错误提示友好
- **express-validator** - 备选方案
  - 与 Express 深度集成

### 日志系统
- **winston** - 日志管理
  - 支持多种传输方式
  - 日志分级
- **morgan** - HTTP 请求日志
  - 记录所有 API 请求

### 开发工具
- **nodemon** - 开发环境自动重启
- **dotenv** - 环境变量管理
- **cors** - 跨域处理
- **helmet** - 安全增强

### 可选增强
- **TypeScript** - 类型安全（推荐）
- **Redis** - 缓存、Session 存储
- **PM2** - 生产环境进程管理

### 架构分层说明

#### 1. **路由层 (Routes)**
- 职责：定义 API 端点，绑定到控制器
- 特点：薄层，只做路由映射和中间件绑定

#### 2. **控制器层 (Controllers)**
- 职责：处理 HTTP 请求，调用服务层，返回响应
- 特点：不包含业务逻辑，只做参数处理和响应格式化

#### 3. **服务层 (Services)**
- 职责：核心业务逻辑
- 特点：可复用，可被多个控制器调用

#### 4. **模型层 (Models)**
- 职责：数据库表结构定义，数据访问
- 特点：ORM 映射，关联关系定义

#### 5. **中间件层 (Middlewares)**
- 职责：请求预处理、认证、权限、日志、异常处理
- 特点：可插拔，可复用

#### 6. **工具层 (Utils)**
- 职责：通用工具函数
- 特点：无状态，纯函数

## 🔐 RBAC 权限设计

### 权限模型

采用 **RBAC (Role-Based Access Control)** 基于角色的访问控制：

```
用户 (User) → 角色 (Role) → 权限 (Permission)
```

### 角色示例

| 角色代码 | 角色名称 | 说明 |
|---------|---------|------|
| admin | 系统管理员 | 拥有所有权限 |
| manager | 经理 | 审批工单、查看所有数据 |
| employee | 普通员工 | 提交工单、查看自己的数据 |
| guest | 访客 | 只读权限 |

### 权限示例

| 权限代码 | 资源 | 操作 | 说明 |
|---------|------|------|------|
| user:create | user | create | 创建用户 |
| user:read | user | read | 查看用户 |
| user:update | user | update | 修改用户 |
| user:delete | user | delete | 删除用户 |
| ticket:create | ticket | create | 创建工单 |
| ticket:approve | ticket | approve | 审批工单 |
| ticket:read:all | ticket | read | 查看所有工单 |
| ticket:read:own | ticket | read | 查看自己的工单 |

### 权限检查逻辑

```javascript
// 检查用户是否有某个权限
hasPermission(userId, permissionCode)

// 检查用户是否有某个角色
hasRole(userId, roleCode)

// 检查用户是否是资源的拥有者
isOwner(userId, resourceType, resourceId)
```

### HTTP 状态码使用

| 状态码 | 说明 | 使用场景 |
|--------|------|----------|
| 200 | OK | 成功（GET、PUT、PATCH） |
| 201 | Created | 创建成功（POST） |
| 204 | No Content | 删除成功（DELETE） |
| 400 | Bad Request | 参数错误 |
| 401 | Unauthorized | 未认证 |
| 403 | Forbidden | 无权限 |
| 404 | Not Found | 资源不存在 |
| 409 | Conflict | 资源冲突（如用户名重复） |
| 500 | Internal Server Error | 服务器错误 |

## 🔧 核心功能实现思路

### 1. JWT 认证流程

```
1. 用户登录 → 验证用户名密码
2. 验证成功 → 生成 JWT Token（包含 userId、角色等）
3. 返回 Token 给客户端
4. 客户端存储 Token（localStorage/sessionStorage）
5. 后续请求携带 Token（Authorization: Bearer <token>）
6. 服务端中间件验证 Token
7. Token 有效 → 解析用户信息 → 继续请求
8. Token 无效/过期 → 返回 401
```

### 2. 权限检查流程

```
1. 请求到达 → JWT 中间件验证身份
2. 从 Token 获取 userId
3. 查询用户的角色和权限
4. 权限中间件检查是否有所需权限
5. 有权限 → 继续执行
6. 无权限 → 返回 403
```

### 3. 工单审批流程

```
1. 员工创建工单（status: pending）
2. 系统通知审批人（可选）
3. 审批人查看工单列表
4. 审批人操作：
   - 批准 → status: approved
   - 拒绝 → status: rejected，填写拒绝原因
5. 记录审批日志
6. 通知创建人（可选）
```

### 4. 文件上传流程

```
1. 客户端选择文件
2. 发送 multipart/form-data 请求
3. multer 中间件处理上传
4. 生成唯一文件名（避免冲突）
5. 保存到 uploads 目录
6. 文件信息存入数据库
7. 返回文件 ID 和访问路径
```

### 5. 日志记录策略

#### 请求日志（morgan）
- 记录所有 HTTP 请求
- 包含：时间、方法、路径、状态码、响应时间

#### 操作日志（数据库）
- 记录重要操作：
  - 用户登录/登出
  - 创建/修改/删除资源
  - 权限变更
  - 审批操作

#### 错误日志（winston）
- 记录所有异常和错误
- 分级：error、warn、info、debug

## 🔒 安全考虑

### 1. 密码安全
- 使用 bcrypt 加密存储
- 加盐轮数：10-12
- 永不在日志中记录明文密码

### 2. JWT 安全
- 使用强随机密钥
- 设置合理过期时间（如 24 小时）
- Token 存储在 localStorage（XSS 风险）或 httpOnly Cookie

### 3. 文件上传安全
- 限制文件大小
- 限制文件类型
- 重命名上传文件（防止覆盖）
- 存储在非 Web 可访问目录

### 4. SQL 注入防护
- 使用 ORM 参数化查询
- 永不拼接 SQL

### 5. XSS 防护
- 输入校验
- 输出转义
- 使用 helmet 中间件

### 6. CSRF 防护
- 使用 Token 验证
- 或使用 SameSite Cookie
